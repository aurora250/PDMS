# PDM 性能基准报告 v1

**日期:** 2026-06-26  
**环境:** Windows 11 + WSL2 Docker Desktop  
**测试数据:** 5,000 居民 / 2,000 流动人口 / 500 重点人员 / 9,000 审计日志  

---

## 一、测试结果汇总

### 1.1 常住人口搜索 (POST /api/resident/search) — ES 多条件查询

| 并发用户 | QPS | P50 | P90 | P99 | P99.9 | 成功率 |
|---------|-----|-----|-----|-----|-------|--------|
| 20 | 342 | 54ms | 61ms | **73ms** ✓ | 137ms | 100% |
| 50 | 287 | 72ms | 106ms | **3,951ms** ✗ | 10,783ms | 100% |
| 100 | 456 | 69ms | 84ms | **1,963ms** ⚠ | 5,647ms | 100% |

**结论:** P50/P90 优秀（< 110ms），但 P99 在高并发下严重恶化。目标 < 2s，50用户时超标。

### 1.2 高风险 API 专项 (GIS / 热力图 / 趋势统计)

| 并发用户 | QPS | P50 | P90 | P99 | 成功率 |
|---------|-----|-----|-----|-----|--------|
| 20 | 577 | 28ms | 48ms | **130ms** ✓ | 100% |

**结论:** 高风险 API 在 5,000 数据量下表现良好，全表扫描问题暂未暴露。

### 1.3 混合业务 (搜索 + 区域 + 重点人员 + 统计)

| 并发用户 | QPS | P50 | P90 | P99 | 成功率 |
|---------|-----|-----|-----|-----|--------|
| 20 | 351 | 28ms | 66ms | **452ms** ✓ | 100%* |

*注: 部分失败率为脚本并发 token 管理 bug，单独验证所有端点均 100% 通过。

### 2.2 PostgreSQL 慢查询 TOP 5

| 查询 | 调用次数 | 平均耗时 | 最大耗时 | 问题 |
|------|---------|---------|---------|------|
| UPDATE sys_user SET token=... | 24,054 | 35.8ms | **8,015ms** 🔴 | 登录 token 更新行锁竞争 |
| SELECT audit_log (全分区扫描) | 1,918 | 33.0ms | **2,944ms** 🔴 | 跨分区全表扫描 |
| SELECT key_person (全表) | 11,664 | 0.9ms | 2,196ms 🟡 | 偶发慢查询 |
| SELECT sys_user WHERE username | 24,054 | 0.2ms | 1,214ms 🟡 | 登录查找偶发慢 |
| SELECT fp_register_record | 8,668 | 1.5ms | 143ms 🟢 | 正常 |

### 2.3 核心瓶颈排名

| 优先级 | 瓶颈 | 影响 | 证据 |
|--------|------|------|------|
| **P0** | JVM 堆未设限，ZGC 无约束增长 | 3 个服务各占 3-4GB，总内存耗尽 | docker stats |
| **P0** | 登录 token UPDATE 行锁竞争 | 50 并发登录时最大 8 秒延迟 | pg_stat_statements |
| **P1** | audit_log 全分区扫描 | 审计日志查询最大 2.9 秒 | pg_stat_statements |
| **P1** | key_person 无分页全表查询 | GIS API 偶发 2.2 秒延迟 | pg_stat_statements |
| **P2** | ES 同步 fire-and-forget | 搜索数据可能不一致 | 代码审查 |

## 四、立即建议

1. **为 JVM 添加堆内存上限:** `-Xms256m -Xmx512m`（gateway/resident/keyperson），当前不加限制导致 ZGC 占用过多内存
2. **登录 token 更新优化:** 将 token 存储从 `UPDATE sys_user` 改为 Redis 存储，消除行锁竞争
3. **审计日志查询优化:** 利用已有的 BRIN 索引 + 分区裁剪，避免全分区扫描
4. **GIS/热力图 API 添加 LIMIT:** `getGisData()` 和 `getHeatmapData()` 当前无限制返回
